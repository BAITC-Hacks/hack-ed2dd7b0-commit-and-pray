# Архитектура: «Аким на 5 часов» — AI-симулятор управления городом

Спец-трек Astana Innovations (HackAlem AI). Источники требований:
официальное ТЗ трека и официальный «Датасет районов» (PDF с формулами,
загружены организаторами).

## Проблема
Городской бюджет (100 условных единиц) нужно распределить между 5
направлениями (транспорт, экология, соцсфера, безопасность, сервисы) через
конкретные мероприятия из каталога, учитывая лаги внедрения, синергии между
мерами и несовместимости — и сразу увидеть эффект на **Astana Quality of
Life Score**.

## Поток данных

```
┌──────────────┐   GET /api/districts, /api/measures     ┌───────────────┐
│   Frontend    │ ───────────────────────────────────────▶│   FastAPI     │
│ (React+Vite)  │                                          │   backend     │
│               │◀─────────────────────────────────────────│              │
│ DistrictCard  │   POST /api/simulate {selections[5]}     │ validator.py  │
│ MeasureSelect │   → {score, district_scores,             │ scoring.py    │
│ QoLGauge      │      district_indicators, explanation}   │ narrative.py ─┼──▶ LLM API
│ VerdictPanel  │                                          │ data.py       │  (опционально,
└──────────────┘                                          └───────────────┘   fallback без ключа)
```

## Компоненты бэкенда
- **data.py** — датасет районов и каталог из 14 мероприятий (M1-M14),
  веса показателей, синергии, несовместимости — константы из официального
  ТЗ, не подлежат "тюнингу".
- **validator.py** — проверка набора решений: ровно 5, бюджет ≤ 100, без
  повторов, район обязателен/запрещён по типу меры, не более 2 мер на
  направление, несовместимости M1↔M3 (в любом районе), M4↔M7 и M5↔M13
  (в одном районе).
- **scoring.py** — детерминированный расчёт Score (см. формулу ниже), без
  LLM — воспроизводимость важнее креативности здесь.
- **narrative.py** — LLM получает уже посчитанные числа (дельты, Score,
  синергии, критические показатели) и формулирует объяснение от лица акима;
  без ключа — fallback-шаблон на тех же числах, демо не ломается.

## Формула Astana Quality of Life Score (раздел 3 ТЗ)

Горизонт симуляции `H = 8` кварталов. Для каждой меры `m` с лагом `L_m`
реализованная доля эффекта = `(8 − L_m) / 8`.

1. **Новое значение показателя** для района `d`, показателя `k`:
   `I'_dk = clip(I_dk + Σ эффект_m,k × (8 − L_m)/8 + синергии, 0, 100)`
2. **Оценка района**: `D_d = Σ w_k × I'_dk` (веса `w_k` заданы по каждому
   из 10 показателей T1/T2/E1/E2/S1/S2/B1/B2/C1/C2, сумма = 1).
3. **Городской балл**: `D_avg = Σ pop_d × D_d` (средневзвешенный по
   населению района).
4. **Итоговый Score**:
   `Score = 0.7 × D_avg + 0.3 × min(D_d) − 1.0 × N_crit`,
   где `N_crit` — число пар «район × показатель» со значением `< 40`
   после всех эффектов (штраф 1 балл за каждую).

Смысл: 70% веса — общий результат по городу, 30% — самый слабый район
(чтобы нельзя было «вылизать» один район и забыть про Нуру), штраф —
чтобы не оставлять провалы.

**Контрольная точка:** базовый Score без единого мероприятия = **52.56**
(0.7×56.86 + 0.3×49.18 − 2, два критических значения — S1 и S2 в Нуре).
Проверено кодом ([backend/tests/test_scoring.py](../backend/tests/test_scoring.py)).

## Роль LLM
По ТЗ: «LLM получает результат расчёта (дельты по районам и показателям,
вклад каждой меры) и объясняет его, сравнивает наборы, советует. Числа он
не считает и не придумывает.» Реализовано ровно так — `narrative.py`
только форматирует уже готовый результат `compute_score()` в текст.

## Технологии
- Backend: Python 3.12+, FastAPI, Pydantic, Uvicorn, pytest
- Frontend: React 19, TypeScript, Vite, TailwindCSS v4, Recharts,
  Framer Motion (анимация gauge)
- LLM: OpenAI-совместимый API (ключ/эндпоинт настраиваются в `.env`)
- Деплой: Docker Compose (backend + nginx-фронтенд с проксированием `/api`),
  либо локальный запуск `uvicorn` + `npm run dev`
